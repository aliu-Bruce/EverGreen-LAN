# EverGreen LAN · 运行手册(P1–P3)

> 目标:多台机器组成一个房间,互相可见、可ping、可联机。
> 全程无中心服务器;房间码是唯一的加入凭证,持码者才推得出会话密钥。

## 0. 前置条件

| 项 | 说明 |
|---|---|
| Go 1.24+ | 构建 core 用 |
| wintun.dll(仅 Windows) | 从 wintun.net 下载,放在编译产物同目录;驱动接口属系统组件,不随源码入库 |
| 管理员权限(仅真实模式) | 建虚拟网卡与配地址是系统级操作,提权弹窗属预期 |
| 多台机器互通 | 同一局域网,或任一可直连的网络路径;UDP 端口 47777 可达(发现另需同网段 UDP 47778) |

## 1. 构建

```powershell
cd core
go build -o ..\egland.exe ./cmd/egland
```

## 2. 免管理员自检(建议先跑)

进程内完成三人房间网全链路:房间码握手与地址分配、成员间单播转发、
广播洪水(游戏局域网发现依赖它)、交付主机本机、错房间码拒绝、
成员名册、防重放;另加 STUN 探测(本地假服务器回显)、发现信标的
收发与非法报文过滤、可靠流(1 MiB 主机与成员往返、第二条独立流),
以及文件传输(512 KiB 主机 → 成员,双端确认、落盘内容与 SHA-256 一致)。

```powershell
.\egland.exe -test-echo
```

预期输出 16 行 PASS 与「全部通过」。

## 3. 局域网发现(免房间码加入)

界面处于空闲态时,核心监听 UDP 47778;同一网段的主机每 2 秒向子网广播地址
发一条 JSON 信标(`eglan` / `name` / `code` / `peer` / `members`)。界面收到后
把房间列在主页,点「加入」即用信标里的房间码与主机地址直连。

- 只在同一广播域内有效(同一 WiFi / 同一交换机);跨网段不会发现。
- 开房后停止监听、改为本机播报;离房或加入失败后自动恢复监听。
- 房间消失:连续 6 秒没有新信标,即从列表移除。
- 信标携带原始房间码,明文只在本网段可见——「同 LAN 即信任」是本版的边界。
- 主机与加入方都需放行入站 UDP 47778;核心启动时尝试自动放行,未提权时
  由用户按系统防火墙工具手工添加。

## 4. 公网直连(异地加入,需端口映射)

公网直连让不在同一网络的朋友也能入房:主机经 STUN 拿到自己在本网出口的
UDP 映射地址,把它写进 `eglan://join/…` 邀请;朋友粘贴邀请即填好房间码与地址。

1. 主机开房后,在房间页「邀请与公网直连」面板点 **探测公网**;
2. 房间页显示公网地址(`IP:端口`),点 **复制邀请** 发给朋友;
3. 朋友在加入页点 **粘贴邀请**(或直接粘贴整段文字),连接房间。

边界与前提:

- **必须有端口映射**:UDP 数据仍直接从主机发向成员,核心不提供打洞或中继。
  需要在路由器把外部 UDP 端口映射到主机的房间端口(默认 47777)。
- **探测端口 ≠ 映射端口时**:STUN 看到的是 NAT 此刻分配的外部端口。若与房间
  端口不同,把「该外部端口」转发到「房间端口」即可,邀请里已带上实际端口。
- **对称 NAT / CGNAT**:映射每次不同或出口不可控时,公网直连不可用,界面会
  提示退回局域网方式。
- **隐私**:STUN 服务器只在用户点「探测公网」或设置页「测试连接」那一刻被访问一次,默认
  `stun.cloudflare.com:3478`,可在设置里更换并在试连成功后保存;除同房成员与该次探测外,
  核心不产生任何其他外联。

## 5. 多机联机实测

**主机(开房间的一侧):**

```powershell
# 以管理员身份运行
cd <exe 所在目录>
.\egland.exe -role host
# 窗口会打印:房间已开放,房间码:XXXX XXXX
# 把房间码告诉想加入的伙伴;本机隧道地址固定 10.66.7.1
```

也可指定自己的房间码:`-code MYCODE1`(归一后作为预共享密钥)。

**成员(加入的每一侧):**

```powershell
# 以管理员身份运行
.\egland.exe -role client -code XXXXXXXX -peer 192.168.x.x:47777   # 换成主机局域网 IP
```

成员的隧道地址由主机从 10.66.7.2 起依次分配,窗口里会显示。

**验证(任一成员侧):**

```powershell
ping 10.66.7.1        # 打到主机,穿过加密隧道
ping 10.66.7.2        # 打到另一成员,经主机转发
```

游戏联机:让游戏检索局域网房间即可——广播与组播会向全房间洪水,
主机房里的游戏应能互相看见(与真实局域网同效)。

### 同机双实例自测的局限

在一台机器上以 `-adapter EGLAN2` 同时跑主机与成员,可验证:真实 Wintun
创建、加密握手与验码、地址分配、广播洪水的物理通路(用网卡收发计数器
对比实证,别信 ping)。但有两处结果失真,属单机环境固有伪影:

- ping 10.66.7.x 无意义:两个地址都是本机地址,IP 栈直接短路应答,
  包不会经过隧道进程。
- 广播副本不被套接字收到:本机同时存在两张 10.66.7.0/24 网卡,
  网段广播的投递被双路由干扰;网卡计数器仍在涨(Rx/Tx 各 +3),
  物理链路是通的。真实部署每机只有一张 EGLAN 网卡,无此冲突。

跨机 ping、游戏互相发现、套接字层投递,以双机实测为准。

## 6. 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `-role` | host | host=开房间;client=加入 |
| `-code` | host 留空自动生成 | 房间码,加入凭证;client 必填 |
| `-name` | Player-系统用户名 | 房间内显示名 |
| `-ip` | 10.66.7.1/24 | 仅 host:本端隧道地址段;多房间并存时错开网段 |
| `-listen` | 47777 | host 监听的房间 UDP 端口 |
| `-peer` | 必填(client) | 主机地址 host:port |
| `-adapter` | EGLAN | 虚拟网卡名;同机多实例用不同名 |
| `-mtu` | 1400 | 隧道 MTU,勿超过路径 MTU |

发现端口固定为 UDP 47778,不随 `-listen` 变化;信标里的 `peer` 是
「网卡地址 + `-listen` 端口」,因此自定义房间端口时加入方仍能连对。

## 7. 故障排查

| 现象 | 原因与处理 |
|---|---|
| `找不到 wintun.dll` | DLL 未放在 exe 同目录 |
| `创建网卡失败(权限被拒)` | 未以管理员运行 |
| `等待主机应答超时` | 主机未启动 / IP 写错 / 防火墙拦 UDP 47777(主机侧启动时自会放行) |
| `等待地址分配超时(房间码不对或主机已满)` | 房间码抄错,或主机侧地址池已满 |
| 主页看不到同 WiFi 的房间 | 双方不在同一网段 / 主机未开房 / 防火墙拦 UDP 47778(双方都要放行) |
| 看得到房间但加入失败 | 主机已退房(信标最多残留 6 秒)/ 信标里的地址不可达 |
| 单播通但游戏搜不到房间 | 游戏走组播发现;确认双方窗口都保持打开 |
| ping 不通但入房成功 | 两端窗口需都保持打开;确认同一房间码 |
| 探测公网超时 | STUN 服务器不可达(部分公司网络拦 UDP 3478);在设置里换一个 STUN 服务器 |
| 探测成功但异地加入失败 | 路由器未把 UDP 端口映射到主机;按房间页提示把外部端口转发到房间端口 |
| 探测到的端口每次都不同 | 对称 NAT / CGNAT,公网直连不可用;退回局域网方式 |
| 退出后残留 EGLAN 网卡 | 控制面板-网络连接中手动删除;下次正常退出会自动清理 |

## 8. 安全边界(P1/P2)

- 会话密钥由 X25519 握手临时生成,叠加房间码作 HKDF 盐:
  不持码者推不出任何一方的钥匙,握手即入房核验,无需明文传码。
- 成员先登记后入房:未凭密钥发出入房证明者停留 pending(10 秒过期、上限 8 人),不占地址。
- 重连按公钥认出,隧道地址保留;地址池满时新成员拿不到地址,自行退避。
- 发现信标在本网段明文广播房间码,范围限于同一广播域;
  信标的版本、名字、房间码、地址逐项校验,非法报文直接丢弃。
- STUN 探测只发一个 Binding 请求,只读取 NAT 映射,不携带房间信息;
  响应须与请求目标同源且事务标识匹配,其余来源一律丢弃。
- 文件传输复用房间的端到端加密链路;接收端校验 SHA-256 后才落成正式文件,
  半途失败只留 `.eglan-part` 临时文件。
- 无遥测、无后台外联;除同房成员与一次显式 STUN 探测外不产生网络流量。
- 长期身份绑定与公网部署的防滥用仍在 P2 清单内。

## 9. 界面通道(-ipc,给界面开发者)

界面程序以子进程拉起 `egland -ipc`,经 stdin/stdout 一行一个 JSON(UTF-8)通信。
需要管理员权限时,旧核心用系统 UAC 拉起新的核心,新核心以
`-ipc-connect 127.0.0.1:端口 -ipc-token 令牌` 连回界面,首行认证后沿用同一行协议;
界面窗口本身始终以普通权限运行。

| 请求 | 应答 |
|---|---|
| `{"op":"start-host"}`(可选 `code`/`name`/`listen`/`adapter`/`mtu`/`cidr`) | `ok` + `state:"hosting"` + `code`(展示形 XXXX XXXX)+ `self` + `port` + `lan`(各网卡 `IP:端口`) |
| `{"op":"join","code":"…","peer":"host:port"}` | 先 `ok state:"joining"`,完成后发事件 `room-up` |
| `{"op":"stop"}` | `ok state:"idle"`;幂等 |
| `{"op":"status"}` / `{"op":"members"}` | `status`(state/code/self)/ `members`(list) |
| `{"op":"stun","server":"stun.example:3478"}` | 从房间套接字探测公网映射;`ok` 带 `ip`/`port`,仅 hosting 时可用,约 4 秒超时 |
| `{"op":"test-stun","server":"stun.example:3478"}` | 用独立套接字试连 STUN 服务器;`ok` 带规范化后的 `server` 与 `ip`/`port`,未开房也可用,约 5 秒超时 |
| `{"op":"env"}` | `{"type":"env","admin":false,"canElevate":true}`:是否已提权、能否一键提权 |
| `{"op":"elevate-core","addr":"127.0.0.1:port","token":"…"}` | 用系统提权弹窗拉起新的核心,新核心连回界面提供的回环端口;成功 `ok relaunched:true`,旧核心随即退出。仅空闲时可用 |
| `{"op":"send-file","to":"10.66.7.2","path":"…"}` | 向房间成员发文件;`ok` 带传输编号 `transfer`。主机可指定任一成员,成员省略 `to` 即发主机 |
| `{"op":"accept-file","transfer":"t1","path":"…"}` | 接受报价并指定绝对保存路径;先写 `<path>.eglan-part`,校验 SHA-256 后改名 |
| `{"op":"reject-file","transfer":"t1","reason":"…"}` | 拒绝接收;`reason` 可选 |
| `{"op":"pick-file","title":"…"}` / `{"op":"pick-save","title":"…","name":"…"}` | 调系统原生打开/保存对话框;`ok` 带 `path`,用户取消时带 `"cancel":true`,平台不支持时返回 `err` |

权限查询只读,不改动系统状态;`elevate-core` 只接受本机回环地址与至少 16 字节的十六进制令牌,
用户取消 UAC 或系统拒绝时返回 `err`,旧核心与界面都保持原状。已在管理员权限下调用时
返回 `ok relaunched:false`。界面本身始终不提权。

空闲时核心监听 UDP 47778,同网段有房间就推事件:

```json
{"type":"event","name":"discovered","rooms":[{"name":"苔石小屋","code":"K7Q2M9XD","peer":"192.168.1.88:47777","members":3}]}
```

列表是完整快照,内容变化或过期时重推;开房后核心改播报并停止监听,
离房、加入失败或 `stop` 后恢复监听。发现加入与普通加入走同一个 `join`,
失败原因由界面在主页内联展示。

房间内收发文件时推传输事件(进度约每 100 ms 一条):

```json
{"type":"event","name":"file-offer","transfer":"t1","peer":"10.66.7.1","file":"存档.zip","size":123456,"incoming":true}
{"type":"event","name":"file-progress","transfer":"t1","done":45678,"size":123456,"incoming":true}
{"type":"event","name":"file-done","transfer":"t1","ok":true,"path":"C:\\…\\存档.zip","size":123456,"done":123456,"incoming":true}
```

接收方需在 2 分钟内接受或拒绝,发送方最多等 3 分钟;传输走可靠流,
与 IP 包共用同一条加密链路。接收端落盘后核对 SHA-256,失败时删除临时文件。

失败一律 `{"type":"err","message":"…"}`;房间因网络错误终止时发 `room-down` 事件。
界面关闭管道即退出,核心自动清理网卡与监听。
